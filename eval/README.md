# RAG 评估集

用于量化知识库改造前后的回答质量。跑一次约 100 秒，56 次模型调用。

## 目录

```
eval/
├── questions.jsonl          50 条测试题，六类
├── run_eval.py              跑批与判分脚本
└── results/                 每次运行的结果（JSON，含逐条回答原文）
```

## 六类题目

| 类别 | 条数 | 考什么 | 当前知识库能否覆盖 |
|---|---|---|---|
| A 等级与年费 | 10 | 精确数字：年费、倍率、折扣、补差价 | 能 |
| B 积分规则 | 10 | 计算公式、到账、兑换、过期 | 能 |
| C 退换货 | 10 | 期限、凭证、退款时效、换货规则 | 章程入库后能 |
| D 门店与配送 | 6 | 地址电话能答；营业时间、配送费、时效不能 | 章程入库后能 |
| E 边界与拒答 | 8 | 虚构等级、跨领域、个人数据，必须拒答或纠正 | 能 |
| F 多轮追问 | 6 | 代词指代、省略主语，考查询改写 | 部分依赖 C 类知识 |
| G 工具调用 | 5 | 查等级、查积分、查订单、号码不存在、索要手机号 | 接工具后能 |

C 类和 D 类后半段是**刻意留的空洞**。它们在基线里全部失败，章程入库后全部通过。这个从 0 到 10 的变化，就是知识库换血的效果证据。

G 类依赖种子数据里的会员手机号（18827578719 卓越、13900000001 卓越），换库或改数据后要同步更新。G02 断言的积分余额同理。

## 运行

```powershell
# 默认打 8081
python eval/run_eval.py

# 打别的端口
python eval/run_eval.py --base http://localhost:8082

# 只跑某一类，改完先局部验证
python eval/run_eval.py --only C

# 加标记，区分基线版和改造后
python eval/run_eval.py --tag baseline
python eval/run_eval.py --tag charter
```

前置条件：应用在跑，且**已经调过 reindex**。向量库为空时所有题都会变成"未找到依据"。

## 判分规则

`expect` 是「组」的列表，组内任一备选片段命中即算满足，所有组都要满足。`forbid` 里的片段只要出现就判失败。

```json
{"expect": [["420"]], "forbid": [["50000"]]}
```

上面这条要求回答出现 420，且不能出现已废弃的 50000 门槛。`forbid` 主要用来抓两类问题：模型编造了不该有的数字，或者还在引用改造前的旧口径。

### 拒答拦截

**非 E 类的题目，如果回答开头 40 字内出现「不确定」「没有准确信息」「不在我的服务范围」这类话术，直接判失败**，不管关键词是否命中。

这条规则是踩坑加上的。第一版跑完，C07（可以换货吗）和 C09（线上线下退货一样吗）都判通过了，但模型实际答的是"我这里没有准确信息，你可以查看山姆会员小程序"——"可以查看"里的"可以"命中了 `expect` 的 `["同款","可以"]`。**关键词判分最典型的假阳性：拒答句里凑巧含有期望词。**

加上拦截后，这两条如实变成失败，C 类从 2/10 修正为 0/10。

### 判分能力的边界

关键词匹配只能验证「关键事实是否出现」，验证不了「表述是否完整准确」。一段答非所问但恰好包含关键词的回答会误判为通过，所以**每次跑完都要人工抽查失败项和部分通过项**。`results/*.json` 里保存了完整回答原文，就是为了这个。

### 100% 不等于没有缺陷

人工抽查 8 条回答后发现一处判分抓不到的问题。E01 问「山姆的钻石会员有什么权益」，正确答出「山姆没有钻石会员，只有白金和卓越」，但紧接着补了一句「具体权益细节我这边没有准确信息」——**它其实有这些细节，只是检索没有把权益章节召回。** 关键词判分只看「有没有出现否定表述」，看不出这种自我降级。

这类问题只能靠人工读原文发现，所以每次跑完都要抽查。

### 接入工具时踩的坑：空上下文不能自定义模板

第一版把 `ContextualQueryAugmenter` 配成 `allowEmptyContext(false)` + 自定义 `emptyContextPromptTemplate`，模板里写了 `{query}`，结果三条跨领域问题（写总结、问天气、写脚本）全部 500：

```
java.lang.IllegalStateException: Not all variables were replaced in the template.
Missing variable names are: [query].
  at StTemplateRenderer.validate
  at ContextualQueryAugmenter.augmentQueryWhenEmptyContext(ContextualQueryAugmenter.java:132)
```

**根因：空上下文分支调用的是 `emptyContextPromptTemplate.render()`，不传任何模板变量。** 所以这个模板里不能出现任何占位符，写了就必崩；而如果不写 `{query}`，原问题会被整段替换掉，模型根本看不到用户在问什么。

两个约束互相矛盾，结论是**空上下文场景不要自定义模板**，改成 `allowEmptyContext(true)`，把问题原样交给模型，拒答约束交给 system-prompt，再用 E 类题目守住。

修完 E 类 8/8 全过，G 类也能正常调工具。

## 加新题

在 `questions.jsonl` 追加一行即可，字段：

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识，建议按类别编号 A01、C03 |
| `category` | 以类别字母开头，`run_eval.py --only` 按前缀过滤 |
| `turns` | 问题列表。只有一条是单轮，两条以上按顺序发同一个 conversationId |
| `expect` | 必须出现的片段，二维数组 |
| `forbid` | 不能出现的片段，可省略 |
| `note` | 这道题在考什么，写给自己看 |

加完先 `--only X` 跑单类，确认判分不会误伤，再跑全量。
