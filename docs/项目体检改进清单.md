### #1 会员等级自动升降级 + 变更记录表永远为空

**问题**：`member_level_change_record` 表建了、Mapper 建了、Controller 接口 `GET /api/member/{id}/level-changes` 也写了，但 **全项目没有任何 Service 写入这条记录**，也没有任何自动升级逻辑。grep `upgrade/升级/autoLevel/changeLevel/promote` 全 Java 返回空。

**影响**：
- 后台"会员详情"若展示等级变更记录 → 永远空
- 论文若写"会员等级根据累计消费自动升降级" → 与代码矛盾，答辩必被问

**修复方案**（在 `OrderServiceImpl.checkout()` 第8步"更新会员消费金额"之后插入）：

```java
// 8.1 自动升级检查
MemberLevel newLevel = checkAndUpgradeLevel(member);
if (newLevel != null && !newLevel.getId().equals(member.getCurrentLevelId())) {
    Long oldLevelId = member.getCurrentLevelId();
    member.setCurrentLevelId(newLevel.getId());
    memberMapper.updateById(member);

    // 写入变更记录
    MemberLevelChangeRecord changeRecord = new MemberLevelChangeRecord();
    changeRecord.setMemberId(member.getId());
    changeRecord.setOldLevelId(oldLevelId);
    changeRecord.setNewLevelId(newLevel.getId());
    changeRecord.setReason("累计消费达到 " + newLevel.getLevelName() + " 标准");
    changeRecordMapper.insert(changeRecord);
}
```

`checkAndUpgradeLevel` 按 `totalConsumption` 阈值匹配最高可达等级（白金→卓越）。阈值可在 `member_level` 表加 `upgrade_threshold` 字段或硬编码（如 50000 元升卓越）。

**涉及文件**：`OrderServiceImpl.java`（加方法+调用）、`MemberLevel.java`（可能加 threshold 字段）

### #2 DataInitializer 管理员密码与实际不一致

**问题**：`DataInitializer.java:67` 用 `passwordEncoder.encode("admin123")` 创建管理员，但 `data.sql` 已插入 admin 密码为 BCrypt("123456")。由于 data.sql 先执行，DataInitializer 的 `if (admin == null)` 跳过创建——所以实际密码是 123456。但日志输出 `"默认管理员账号已创建: admin / admin123"` 具有误导性。

**影响**：新人看代码/日志会困惑；如果某天 data.sql 不执行（干净库），密码变成 admin123 与文档不符

**修复**：DataInitializer 第 67 行改为 `encode("123456")`，第 72 行日志改为 `"admin / 123456"`

**涉及文件**：`config/DataInitializer.java`（2 行）

### #3 下单时同一商品出现多次可导致超卖

**问题**：`OrderServiceImpl.checkout()` 循环1校验库存时，每个 CartItem 单独 `selectById` 读原始库存。如果购物车里同一商品出现两次（qty=3 和 qty=5，库存=7）：
- 校验阶段：3<7 ✓，5<7 ✓ （都通过）
- 扣减阶段：第一次扣 3→剩4，第二次扣 5→**-1**（超卖！）

**影响**：并发或恶意请求可导致负库存；毕设演示中用户不太可能加两次同商品，但代码审查会被发现

**修复**：在校验前按 productId 聚合数量：

```java
// 在循环1之前，聚合同商品数量
Map<Long, Integer> qtyMap = dto.getItems().stream()
    .collect(Collectors.groupingBy(CartItemDTO::getProductId,
        Collectors.summingInt(CartItemDTO::getQuantity)));
// 循环1用 qtyMap 校验
for (Map.Entry<Long, Integer> entry : qtyMap.entrySet()) {
    Product product = productMapper.selectById(entry.getKey());
    if (product.getStockQuantity() < entry.getValue()) {
        throw new BusinessException("商品[" + product.getProductName() + "]库存不足");
    }
}
// 循环3用 qtyMap 扣减（每个商品只扣一次）
```

**涉及文件**：`OrderServiceImpl.java`（checkout 方法重构）
